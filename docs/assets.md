# Asset Inventory and Migration Contract

**Status:** Initial inventory and publishable-tree parity, reviewed 2026-08-16. Provenance details are tracked separately in [the provenance register](assets-provenance.md).

## Inventory

The legacy `static/` tree contains 111 image files, 5 music tracks, 7 sound effects, `favicon.ico`, and `robots.txt` (125 retained files total). The files are retained as project assets; no licensing or provenance claim is made by this inventory.

The root Angular application now uses the retained `static/` tree directly. The isolated prototype copy was removed after root build output verified the migrated assets.

## Current usage

- Character definitions reference typed idle assets for Wizard, Samurai, and Warrior.
- The enemy catalog references typed idle assets for all 18 observed enemy definitions, including the three sequential Gold Slime boss encounters.
- `src/app/domain/assets.ts` centralizes music, sound, and item paths for future adapters.
- The active root UI uses idle character/enemy sprites in character selection and combat views. Relics now render as quality-colored Lucide icons; the retained item images remain historical assets, not active relic art. Observed Evil Tree and slime attack/defeat GIFs are typed as optional enemy assets and rendered through a scheduler-backed 600 ms enemy-attack window; Wild Huntress, Evil Wizard, Fire Worm, Martial Hero, and Witch Blue use observed attack strips during enemy attack windows, with Evil Wizard's `Attack2.png` and Witch Blue's vertical `B_witch_charge.png` selected provisionally for Magic, while all other enemies fall back to their physical attack asset or idle art for attack states. Wizard and Samurai use observed single-row `Idle.png` strips for combat idle states, and Evil Wizard, Fire Worm, Knight, Martial Hero, Wild Huntress, and Witch Blue use mapped idle strips for enemy combat states. Wizard and Samurai use their observed single-row `Attack1.png` strips for physical actions, their observed `Attack2.png` strips provisionally for Magic, and `Hit.png`/`Take Hit.png` strips when receiving damage; Wild Huntress, Evil Wizard, Fire Worm, Martial Hero, and Witch Blue use observed hit strips on non-miss player damage and observed defeat strips as provisional defeat animations. Warrior intentionally falls back to idle art. The application port triggers bundled attack, magic, coin, potion, error, enemy-killed, and legacy level-up sounds plus character-select/dungeon/boss/store music lifecycle. Accessible music/effects volume controls now persist in the Angular preferences envelope; autoplay policy, failure handling, mute labels, and final animation timing remain unresolved.

The counts above are repository observations from `static/`; rerun `find static/images -type f`, `find static/music -type f`, and `find static/sounds -type f` when assets change. `npm run inspect:assets` reports PNG/GIF dimensions for frame-geometry review and accepts `--json` for tooling. `npm run verify:asset-geometry` discovers every typed `SpriteStripAsset` in the active source and verifies its PNG frame geometry; the mapped horizontal idle strips use their observed frame widths/counts, while the Witch Blue idle strip records a nine-frame vertical layout, its attack strip records an observed two-pixel trailing crop explicitly, and its damage strip records a five-frame vertical layout with a 16-pixel trailing crop. `npm run verify:assets` checks the 81 active typed idle/animation/item/music/sound paths, source-reference parity, the exact deferred register, and the expected 42-file deferred image boundary. When passed `dist/hexakill/browser`, it additionally verifies path and SHA-256 byte parity for all 125 retained files in the publishable static tree.

## Migration rules

1. Preserve asset paths or record an explicit replacement mapping.
2. Do not remove retained `static/` assets until the active Angular production output has been verified.
3. Classify each retained image as meaningful, decorative, or animation source and provide accessible text behavior at the UI boundary.
4. Verify audio loading, user-gesture policy, mute controls, reduced-motion behavior, and failure handling before release.
5. Complete provenance/licensing review before publishing retained or replacement assets.

The geometry inspector is descriptive only: it does not infer frame counts, animation semantics, accessibility behavior, or licensing permission. Those remain review decisions recorded in the sprite-source and provenance registers.
