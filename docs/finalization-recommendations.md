# Finalization Recommendation Guide

**Status:** Recommendations only; none of the choices below is an accepted product decision. Reviewed 2026-08-16.

This guide narrows the remaining owner decisions in [the finalization packet](decision-packet.md). It is intentionally separate from accepted ADRs: a future agent may use the recommended order and acceptance evidence, but must not treat a recommendation as permission to change gameplay, assets, hosting, or product scope.

## Recommended resolution order

1. Resolve player initialization and store semantics together, because both change opening combat, progression, and browser fixtures.
2. Resolve local-data migration and product scope before adding persistence fields or service boundaries.
3. Complete the accessibility review and asset provenance review before publishing the media-heavy UI.
4. Select the presentation system and authorized hosting target before calling a release candidate complete.
5. Record each accepted outcome as an ADR, update characterization fixtures, and rerun `npm run verify:release`.

## Agent guardrails

- Do not convert a recommendation into an implementation change without an accepted ADR or an explicit owner instruction.
- Do not call the project complete while any decision packet row or manual acceptance item remains open.
- Keep the current Angular behavior as a characterized provisional baseline so every accepted change can be compared against it.
- Use the full release command after accepted changes; a green local baseline does not prove provider ownership, asset rights, or manual accessibility acceptance.
